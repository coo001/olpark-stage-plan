# 올팍 무대도면

올림픽공원 공연장에 **답사 전에 무대부터 놓아 보는** 무료 웹 도구. 한국체육산업개발이 공개한 공연장 3D 모델 위에 무대 덱·트러스·조명·스피커·콘솔·객석·펜스·세트를 놓고, 기관 공개 제원으로 점검하고, 평면도·장비 목록·공유 주소·무대설치 계획서(서식 제7호) 초안을 뽑는다.

- 열기: `index.html`을 더블클릭(로컬) 또는 GitHub Pages 주소. 서버·키·가입 없음.
- 편집기: `plan.html?v=woori`, `plan.html?v=88`, 사례 `plan.html?case=woori`, `plan.html?case=park88`
- 사례 결과 모음: `examples/` — 사례 2건을 편집기에서 그대로 내보낸 평면도 PNG·장비 CSV·무대설치 계획서·점검 결과. WebGL을 못 켜는 환경에서도 볼 수 있다. 다시 뽑기: `node tools/examples.mjs <주소> <repo>`(작업 폴더 도구)

## 구조
- `app/plan.js` 편집기, `app/checks.js` 장비 종류·점검 계산 → `npm run build` → `assets/plan.js`
- `data/venues.js` 공연장 제원·출처, `data/cases.js` 설계 사례(가정), `data/events.js` 행사 목록
- `models/*.glb` 웹용 모델, `models/*.glb.js` file:// 로 열 때 쓰는 base64 사본

## 계산 방법과 한계
- 바닥 높이는 3D 모델에 아래로 광선을 쏴 찾는다(객석 단차·잔디 경사). 콘솔 시야는 콘솔 눈높이→무대 위 1.7m 직선이 장비 상자·모델 구조물에 걸리는지 본다(three-mesh-bvh).
- 점검마다 기준 앞에 근거를 표시한다: 기관 데이터(무대운영 자료 제원, 공개 행사 목록) / 3D 모델 계산 / 업계 관행·참고(딜레이 60m, 조명 30~60°) / 가정(지정석 0.5×0.9m, 스탠딩 ㎡당 2명, 트러스 12kg/m). '적합'은 안전 승인이 아니다.
- 덧마루 보유 면적: 1.2×1.8m×18 = 38.9㎡ + 0.9×1.8m×18 = 29.2㎡ = 68.0㎡.
- 공연일 겹침: 계획서 공연일(예: 2027년 3월 20일)을 읽어 같은 공연장으로 표기된 공개 행사 기간과 겹치는지 본다. 겹치지 않아도 '참고(목록에 없음)'로만 표시한다. 비공개 대관은 목록에 없으므로 대관 가능 여부는 기관에 문의해야 한다.
- WebGL을 켤 수 없는 브라우저에서는 3D 대신 이유, 편집기를 여는 방법(PC 크롬·엣지 그래픽 가속 켜기, `chrome://gpu` 확인), `examples/` 결과를 보여 준다.
- 모델은 정점을 줄였다(우리금융아트홀 약 8%). 답사·실측을 대신하지 않는다. 검증: 모델의 객석 앞 바닥→무대 높이 1.07m = 기관 제원 1m7cm.
- 한국체육산업개발 공식 서비스가 아니다. 배치는 주소(#p=…)에만 담기고 전송되지 않는다.
